## 内容
管理者は、製造を委託するメーカーを、連絡先・対応商品（対応する商品種別）・商品別単価・製造データの共有方式などの情報とともに登録できる。登録済みのメーカーは、一覧で確認し、内容を編集し、不要になったものは削除できる。共有方式にポータルを選ぶ場合は、メーカーがポータルにログインするためのパスワードを設定する。

## 背景・理由
背景は未確認（既存実装からの逆算のため）。受注品の製造を外部メーカーに委託するため、連絡先・対応可能な商品・単価・製造データの受け渡し方法を管理するメーカーマスタが必要となる。

## 詳細
管理者はメーカー管理画面からメーカーを登録・編集・削除し、一覧を閲覧する。メーカー名は一意で、重複登録は 409 で拒否される。共有方式（sharing_method）が portal の場合はパスワードが必須で、最小8文字・ハッシュ化して保存する。対応商品は商品種別の配列（supported_products）、商品別単価は JSONB（unit_prices）として保持する。削除は物理削除で行われる。メーカーの通知設定は本要件とは別のエンドポイントで管理する。

主なエンドポイント:
- `GET /manufacturers` — メーカー一覧を取得する
- `POST /manufacturers` — メーカーを新規登録する（名称一意、portal 時はパスワード必須）
- `PATCH /manufacturers/{id}` — メーカーを編集する
- `DELETE /manufacturers/{id}` — メーカーを削除する（物理削除）

## 受入基準
- [x] `POST /manufacturers` で、連絡先・対応商品（supported_products）・商品別単価（unit_prices）・共有方式（sharing_method）とともにメーカーを新規登録できる
- [x] メーカー名が既存と重複する登録は 409 で拒否される
- [x] 共有方式が portal の場合はパスワードが必須で、最小8文字・ハッシュ化して保存される
- [x] `PATCH /manufacturers/{id}` で、登録済みメーカーの内容を編集できる
- [x] `DELETE /manufacturers/{id}` で、メーカーを削除できる（物理削除）
- [x] `GET /manufacturers` でメーカー一覧を取得できる

## スコープ外
- メーカーの請求／銀行口座情報は管理者画面では編集・取得できず、メーカー本人がポータルで管理する（REQ-0023）。
- 発注上限（daily_order_limit）は保存されるが、受注制限としては未強制（宣言的メタデータに留まる）。
- メーカーの通知設定は本要件のCRUDとは別のエンドポイント（notification-settings）で管理する。
- 削除は物理削除であり、過去の受注が参照しているメーカーを削除した場合の整合性は担保していない。
