## 内容
管理者と製造委託先（メーカー）では扱える範囲が異なるため、それぞれの権限が明確に分離され、相手方の機能や画面には入り込めないよう保護されている。

## 背景・理由
背景は未確認（既存実装からの逆算のため）。管理者向けの機能・画面と製造委託先向けの機能・画面を混在させず、利用者の種別に応じて適切な範囲だけを許可するために、権限の分離と保護が必要となる。

## 判断が出ないと止まるもの
なし

## 詳細
バックエンドAPIは、リクエストに付与されたトークンの種別とロールを検証したうえで処理を許可する。管理者向けAPIは管理者トークンを要求し、権限がなければ拒否（403）する。メーカー向けAPIはメーカートークンを要求する。フロントエンドは、管理画面・メーカーポータルそれぞれにクライアント側の認証ガードを設け、未認証・種別違いの利用者を該当画面に入れないよう制御する。ルート保護のための Next.js middleware は用いておらず、実効的なアクセス制御はバックエンドAPI側の検証に集約している。

## 受入基準
- [x] 管理者トークンを持たない利用者が管理者向けAPIにアクセスすると 403 で拒否される
- [x] メーカー向けAPIはメーカートークン（種別 `manufacturer`）を要求し、種別が一致する場合のみ処理する
- [x] 管理画面・メーカーポータルにはクライアント側の認証ガードがあり、未認証の利用者は該当画面に入れない
- [x] ルート保護は Next.js middleware ではなくクライアント側ガードとバックエンドAPIの検証で実現されている

## スコープ外
- ルート保護は Next.js middleware では行わず、クライアント側ガードとバックエンドAPIの検証に限定している
