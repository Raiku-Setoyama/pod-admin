## 内容

テスト名は振る舞いを検証すると謳っているのに、実際には同語反復（トートロジー）を assert しているだけのテストがある。実装を検証する形に書き直したい。

## 背景・理由

REQ-0041 の実装中、ruff の `F841`（未使用変数）を是正する過程で見つかった。

`api/tests/unit/test_shipment_pending_orders.py` の `TestPendingOrderStatus` にある 3 件のテストは、次の形をしていた。

```python
def test_preparing_status_when_not_all_items_delivered(self):
    """AC-01: Order with items not all DELIVERED should have status 'preparing'."""
    order_items = [...]              # 組み立てるが一切使われない
    status = PendingOrderStatus.PREPARING
    assert status == PendingOrderStatus.PREPARING   # 常に真
```

`order_items` は組み立てられるだけで使われず、アサーションは定数どうしの比較で常に真になる。**production コードを一行も呼んでいない。** テスト名が主張する「明細が全て DELIVERED でなければ preparing になる」という仕様は、実際には検証されていない。

REQ-0041 では未使用変数の除去のみ行い（振る舞いを変えないため）、テストの中身には手を触れていない。結果として、現在は「何も検証していないことが一目で分かる」状態になっている。

同種のテストが他にもある可能性があるため、洗い出しを含めて扱う。

## 判断が出ないと止まるもの

- 検証したい仕様が何かの確認（`PendingOrderStatus` の導出ロジックは現在 production 側のどこにあるのか）。
- 同様のテストを機械的に洗い出す基準をどう決めるか。
