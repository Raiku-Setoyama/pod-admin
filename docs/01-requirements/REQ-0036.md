## 内容
管理者は、外部販売サイト（受注元）を管理画面から自力で登録・編集でき、その受注元向けの API キーを発行し、受注元ごとに有効・無効を切り替えられる。開発者に依頼したりデータベースを直接操作したりしなくても、新しい販売サイトからの受注取り込みを開始・停止できる。

## 背景・理由
現状、受注元（order_sources）は seed スクリプトでのみ作成でき、管理画面や API から登録・編集・有効無効の切替を行う手段がない。そのため、新しい外部販売サイトを追加したり API キーを発行したりするには開発者の作業が必要で、顧客（管理者）が自力で受注元を追加・運用できない。API キーは平文で保存されており、発行・ローテーションの導線もない。

## 判断が出ないと止まるもの
- 受注元の CRUD をやると決めるか（誰が・どの頻度で受注元を追加する想定か）。
- API キーの扱い（平文のままにするか、ハッシュ化・ローテーションまで求めるか）。

## スコープ外
現時点では、受注元ごとの詳細な権限設計や利用状況のレポートは対象としない。

## 未決事項
受注元の管理 CRUD 画面・API を新設する方向で提案する（priority: future）。API キーの保存方式（平文継続かハッシュ化・ローテーション導入か）は [NEEDS-DECISION: ADR-0020] で決める。

## 実装メモ
現状の実装状況と欠落箇所（inv-2 の発見事項に基づく）:
- 受注元マスタ order_sources（code unique / api_key unique・平文 / is_active / 配送元情報）はテーブルとして部分実装されているが、管理 CRUD の API と画面が無く、seed スクリプトでのみ作成できる。
- API キーは平文保存で、ハッシュ化・ローテーションの仕組みが無い。
- 認証は受注元照合による API キー認証（X-API-Key、order_sources 駆動）で行われている。
