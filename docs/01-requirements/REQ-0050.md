## 内容

配送一覧は、指定した表示件数（既定 20 件）を超える行を 1 ページに表示する。
また、ページ送りの意味が実配送と準備中注文でずれている。**これを直すかどうかの判断をいただきたい。**

## 背景・理由

配送一覧は実配送と準備中注文を別々に取得して連結しているため、
**同じ `page` / `limit` が両方に別々に効く**（`app/services/shipment_service.py` の
`list_with_pending_orders`）。結果として:

- `limit=20` でも 1 ページに最大 40 行が表示される
- 総件数が「実配送の件数 + 準備中注文の件数」の単純な合計になっており、
  ページ数の計算と実際のページ送りが一致しない
- 一方が尽きたあとのページでは、もう一方だけが表示される

ADR-0025 で統合方式は現状維持（選択肢 B）と決まったため、
**この挙動は並び替え（REQ-0049）を入れても残る。**
気づいた事象を落とさないために起票しているが、**要求としてお預かりしたものではない。**

なお `docs/00-charter/nfr.md` には「一覧系 API はページング（既定 20 件・最大 100 件）」と
補足があるが、目標値は「未確認」であり受入基準の形になっていない。
そのため不具合ではなく要件として起票している（AGENTS.md「判定がつかない → 要件に倒す」）。
