## 内容
外部の販売サイトなどからの連携リクエストはAPIキーで認証し、システム内部の処理をトリガーするリクエストは内部処理用のシークレットで認証する。正しいキー・シークレットを持たないリクエストは受け付けない。

## 背景・理由
背景は未確認（既存実装からの逆算のため）。外部販売サイトとのAPI連携や、システム内部からトリガーされる処理を、利用者ログインとは別の仕組みで安全に受け付けるために、APIキーおよび内部シークレットによる認証が必要となる。

## 詳細
外部連携リクエストは HTTP ヘッダ `X-API-Key` にAPIキーを付与し、システムは連携元（order_sources）の情報を用いてこのキーを検証する。内部処理用リクエストは HTTP ヘッダ `X-Internal-Secret` にシークレットを付与し、システムは定数時間比較（タイミング攻撃対策）でこれを検証する。いずれも検証に失敗したリクエストは拒否される。
