## 内容

REQ-0067 で製造データの生成をワーカーの中へ移したあと、使わなくなった
製造データ生成 VM（illustrator-vm）と、VM のためだけにあるネットワーク・監視・設定を撤去する。

## 背景・理由

VM は止めていてもディスク（100GB の pd-ssd）の費用がかかり、Windows とネットワークの設定が
Terraform とドキュメントに残り続ける。一方で、本番を切り替えた直後は、新しい生成で問題が出たときの
切り戻し先として VM を残しておきたい（ADR-0039）。そのため、撤去は切り替えから期間を置いて別に行う。

## 詳細

撤去の対象（2026-10-11 時点の Terraform による）:

- `infra/modules/illustrator-vm/`（VM 本体・予約した内部 IP・サービスアカウント）
- `infra/modules/network/`
  - VM 用サブネット `pod-admin-illustrator`
  - Cloud NAT `pod-admin-nat`、Cloud Router `pod-admin-router`
  - ファイアウォール（Cloud Run → VM、IAP → VM）
  - ワーカーの Direct VPC egress 用サブネット `pod-admin-run`。ワーカーの VPC egress を外すので不要になる
- ワーカーの設定 `ILLUSTRATOR_VM_*` と、Terraform の `illustrator_vm_base_url`・`worker_vpc_egress`
- ドキュメントの VM の記述（`docs/00-charter/constraints.md`、`infra/README.md` の VM の章）

## 受入基準

- [ ] 本番の切り替え（REQ-0067）から 1 か月以上、新しい生成で切り戻しが要る問題が出ていないことを確認したうえで撤去すること
- [ ] VM・VM 用サブネット・Cloud NAT・Cloud Router・VM 向けファイアウォールが Terraform から削除され、本番に残っていないこと
- [ ] ワーカーが VPC に接続されていないこと
- [ ] `ILLUSTRATOR_VM_*` の設定と、Terraform の `illustrator_vm_base_url`・`worker_vpc_egress` が無くなっていること
- [ ] 憲章（`constraints.md`）と `infra/README.md` に VM を前提とする記述が残っていないこと

## スコープ外

- Adobe Illustrator のライセンス解約（システム外の運用作業）
- illustrator-vm リポジトリのアーカイブ
