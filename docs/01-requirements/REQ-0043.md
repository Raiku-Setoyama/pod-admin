## 内容

`AGENTS.md` は「`openapi/schema.yaml` を正本に、`web` は `npm run generate:api-types` で型を生成する」と定めているが、**`openapi/` ディレクトリがリポジトリに存在しない**。規約どおりに型生成できる状態へ戻したい。

## 背景・理由

REQ-0041 の実装中に、フロントの型 `web/src/types/api/index.ts` がバックエンドの契約とずれていることが判明した。具体的には `OrderResponse` が返す `order_source_id` がフロントの `Order` 型に無く、テストのモックとの不整合として表面化した。

原因を追うと、次の状態にあることが分かった。

- `web/package.json` の `generate:api-types` は `openapi-typescript ../openapi/schema.yaml -o src/types/api/generated.ts` を指すが、`openapi/schema.yaml` が存在しないため**実行できない**。
- 実際に使われている `web/src/types/api/index.ts` は生成物ではなく**手で管理されている**（`generated.ts` も存在しない）。
- `api/scripts/export_openapi.py` は存在するので、FastAPI 側からスキーマを書き出す手段はある。

正本が無いまま手管理を続けると、今回のような drift が積み上がり、フロントとバックの契約が静かにずれていく。REQ-0041 で tsc を必須化したため、drift は型エラーとして検出できるようになったが、**検出できるのはテストのモックが触っている範囲だけ**である。

## 判断が出ないと止まるもの

- `openapi/schema.yaml` を CI で生成・検証するのか、コミットして正本として管理するのか。
- 手管理の `src/types/api/index.ts` を生成物へ置き換えるか、当面併存させるか（既存 import の書き換え範囲に影響する）。
