## 内容

製造データ（.ai／.pdf）を、Windows VM 上の Adobe Illustrator（illustrator-vm）で作るのをやめ、
**製造データ生成ワーカーの中で、OSS のベクター編集ツール VectorCraft を使って作る。**
製造委託先に渡すデータの中身は今と変えない。費用を下げ、VM 由来の停止をなくすことが目的である。

**生成は管理システムの API サーバー（`pod-admin-api`）とは別のサーバーで動かす。**

## 背景・理由

### 費用

VM（e2-standard-2・Windows・24 時間稼働）は月 ¥23,099 かかる（`docs/gcp-deployment-cost-review.md`）。
ほかに Adobe Illustrator のライセンス（GCP の外）と、ライセンス確認のための Cloud NAT がかかる。
受注量は小さく、同じ商品の再注文はキャッシュで再生成しないため、生成そのものの負荷は小さい。

### 停止と運用の手間は、すべて Windows・GUI・Adobe ライセンスに由来する

- 自動ログオンが外れて、毎朝 約 9.5 時間止まった（illustrator-vm Issue #5）
- RDP 切断でフリーズした。外部からプロセスが kill され、2026-09-27〜10-02 の 5 日間止まった（REQ-0063, REQ-0064）
- Illustrator のハング、スクリプト確認ダイアログ、1 件ごとの起動
- Adobe のサインインとハードウェア ID がディスクに残るので、VM を作り直せない
- デプロイのたびにワーカーの定期起動を止める必要がある。直列処理なのでステージングと共有できず、
  ステージングでは生成を止めている
- スクリプトのログが VM の中にしか残らない（REQ-0066、BUG-0003 の調査で発覚）

### 検証済みであること

2026-10-08〜10-11 に、illustrator-vm の各商品の処理を VectorCraft 0.4.0 に移して検証した。
検証コードは illustrator-vm のブランチ `claude/illustrator-oss-alternative-daa9da` の `research/vectorcraft/` にある。

- **製造委託先の確認:** アクリルキーホルダー・アクリルスタンド・T シャツのサンプルで OK が出た（2026-10-10）
- **Illustrator 版との差:** カットラインの差は平均 0.08〜0.17mm、白版の重なりは 99% 以上。
  画像の配置の差は 0.001mm 以下、色の差は ΔE00 平均 0.22〜0.85
- **Cloud Run と同じ linux/amd64 で動くこと:** CPU 1・メモリ 1GiB で全商品が成功した（ピークメモリ 289MB）。
  1 件あたり 1 秒前後

## 詳細

### 構成

- 生成処理は `pod-admin-worker`（Cloud Run Job）の中で直接呼ぶ。VM への HTTP 呼び出し・ポーリング・ダウンロードは無くなる
- 生成に必要なもの（VectorCraft の実行ファイル、ICC プロファイル、テンプレート、画像処理ライブラリ）は
  **ワーカー用のイメージにだけ入れる。** `pod-admin-api` のイメージには入れない
- 構成を選んだ理由は ADR-0039

### 出力（製造委託先に渡すもの）

| 商品 | 形式 | 中身 |
|---|---|---|
| T シャツ・トート | PDF | テンプレートどおりの位置に画像を配置。埋め込みプロファイルは「sRGB IEC61966-2.1」 |
| キーホルダー・スタンド・ステッカー | .ai（Illustrator 8 形式） | CutLine（K100 の線）／ColorPrint（CMYK 画像）／White（K100 の複合パス）の 3 レイヤー |

- アクリル系の .ai は、Illustrator で開いたときにレイヤーが残る旧形式（Illustrator 8 形式）で書く。
  VectorCraft の標準の .ai では、Illustrator で開くとレイヤーが 1 枚にまとまるためである（ADR-0039）
- ファイル名の規則は今と同じにする

### 白版の抜けを自動で埋める

販売サイトの白版画像は、デザインのうち半透明でほぼ白の部分（白い羽の模様など）を白版から外していることがある。
透明アクリルではそこが透けるため、製造委託先から指摘を受けた（2026-10-09）。
**白版画像は生成の前に次のとおり直す。** 直した版で製造委託先の OK が出ている。

- 白版の内側に閉じた穴のうち、下の印刷画像に絵があるものを埋める。完全に透明な穴（本当の抜き）は残す
- 外周の切れ込みのうち、下の絵が半透明のもの（穴と同じ原因でできたもの）を埋める
- 白版の内寄せ（0.1mm）でつぶれてしまう小さな孤立点を消す

### 例外・エッジケース

- アクリルスタンドの差し込みタブは ADR-0038 に従う（土台を最下点まで延ばす。合成できなければ失敗させる）
- 生成処理そのものが起動できない（実行ファイルが無い・起動しない）ときは、入力の誤りではないので
  `failed` にせず `pending` のまま残す。今の「VM に届かない」と同じ扱いにする
- 入力の誤り（必須レイヤーの不足、画像として読めない、タブを合成できない等）は、今どおり `failed` にする

## 受入基準

- [x] ワーカーが VM を呼ばずに、T シャツ（S/M/L/XL）・トート（M）・アクリルキーホルダー（50/70/100、白版あり・なし）・アクリルスタンド（50/70/100）・ステッカー（50/70/100）の製造データを生成し、保存して `ready` にすること
- [x] 生成に必要な実行ファイルとライブラリが、ワーカー用のイメージにだけ入り、`pod-admin-api` のイメージには入らないこと
- [x] アクリル系の .ai を Illustrator で開くと、CutLine／ColorPrint／White の 3 レイヤーに分かれ、カットラインは K100 の線（塗りなし）、白版は K100 の複合パス 1 つ、画像は CMYK であること
- [x] T シャツ・トートの PDF のアートボードの大きさと画像の配置が、VM 版と同じであり、埋め込みプロファイルが「sRGB IEC61966-2.1」であること
- [x] 白版画像の、絵がある穴と半透明による外周の切れ込みが埋まり、完全に透明な穴は残ること
- [x] アクリルスタンドの差し込みタブが ADR-0038 に従うこと（土台の延長、タブがテンプレートと同一、合成できなければ `failed`）
- [x] 出力ファイル名が VM 版と同じ規則であること
- [x] 生成処理を起動できないとき、行が `failed` にならず `pending` のまま残り、ワーカーのヘルス確認が NG としてログに残ること
- [x] ステージングでも製造データの生成が動くこと
- [x] 各商品の生成結果の構造（レイヤー・色・大きさ）を確かめる自動テストがあること

## スコープ外

- VM と、VM のためのネットワーク・監視・設定の撤去（REQ-0068。切り戻し先として、本番の切り替え後もしばらく残す）
- Adobe Illustrator のライセンス解約（システム外の運用作業）
- マグカップ（pod-admin の商品種別に無い）
- 販売サイト側の白版画像の作り方の修正

## 実装メモ

コードはすべて 1 本目の PR（`feat/REQ-0067-in-worker-generation`）に入れる。
「ステージングでも動くこと」はマージ後に確かめ、別の PR で `done` にした（経緯の表）。
切り替えの順序と切り戻しは `infra/README.md`「製造データ生成を VM からワーカーへ切り替える」。

- 生成のコードは `api/app/generator/`。illustrator-vm の ExtendScript を VectorCraft のコマンドに移したもの
- アクリルスタンドの土台は「長さ 3mm 以上の水平な辺」とした（ADR-0038 は長さを決めていない）。
  VectorCraft のトレースは丸い輪郭にも 1.1〜1.3mm の水平な直線を作ることがあり、これを土台と誤認すると、
  土台の無い入力に小さな台を付けてタブを合成してしまう。illustrator-vm の回帰テスト用の画像
  （土台の無い円）は、この条件で Illustrator 版と同じく失敗になる。販売サイトの土台は検証した入力で 4.5mm 以上だった
- そのため、土台の無い絵柄（キーホルダー用の画像をスタンドに流したもの）は、Illustrator 版がたまたま
  タブを付けていた入力でも失敗になる（ADR-0038 の「土台が見つからない入力は失敗させる」に沿った結果）
- カットラインのなめらかにする処理（5pt 間引き）は Illustrator 版と同じ。製造委託先の確認を通した
  サンプルとバイト単位で同じ出力になることを確かめてある
