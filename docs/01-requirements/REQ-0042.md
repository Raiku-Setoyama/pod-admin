## 内容

`main` の時点でテストが赤いまま放置されている。失敗を解消し、pytest / vitest を CI の必須チェックに組み込みたい。

## 背景・理由

REQ-0041（静的解析の是正）の着手前にベースラインを実測したところ、**静的解析とは別に、テスト自体が既に失敗している**ことが判明した。REQ-0041 は「振る舞いを変えない」ことを完了条件にしているため、この失敗には手を触れていない。

2026-08-07 時点の main（`c394ce2`）の実測値:

| スイート | 結果 |
|---|---|
| pytest（全体） | 46 failed / 552 passed / 2 skipped / 139 errors |
| pytest（unit のみ） | 44 failed / 545 passed |
| vitest | 9 failed / 245 passed |

- pytest の 139 errors は `tests/integration/` が PostgreSQL への接続を前提にしているため。CI で動かすには DB の準備が要る。
- pytest の unit 失敗 44 件は DB 非依存であり、コードとテストのどちらかが古い可能性が高い。
- vitest は実行ごとに失敗数が 9〜11 件で揺れており、**フレーキーなテストが混ざっている**。

テストが赤いままだと、CI の必須チェックにできず、退行を検出できない。REQ-0041 で静的解析は必須化できたが、テストは対象外のままである。

## 判断が出ないと止まるもの

- 失敗しているテストを直すのか、仕様が変わって不要になったテストとして削除するのか（個別判断が必要）。
- CI で integration テストを動かすか（PostgreSQL のサービスコンテナを用意するか）。
- フレーキーなテストへの対処方針。
