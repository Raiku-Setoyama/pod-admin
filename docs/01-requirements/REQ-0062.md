## 内容

製造データ生成 VM（`illustrator-vm`）のブートディスクを、**壊れても戻せる形にする。**

## 背景・理由

**このディスクはシステムで唯一の再現不能資産である。** 上に Adobe Illustrator の
インストールと **Adobe CC のサインイン状態**が乗っており、作り直すと
ハードウェア ID が変わってライセンス認証をやり直すことになる。
REQ-0055 はこれを「**この移送で唯一読めなかったリスク**」と記録している。

いま守りは 2 つあるが、**どちらも「消えない」ことしか保証していない。**

| 仕掛け | 何を防ぐか | 防がないもの |
|---|---|---|
| `deletion_protection = true` | Terraform と API からの削除 | **中身の破損**（Windows Update の失敗、ファイルシステムの破損、誤操作） |
| `ignore_changes`（イメージ） | イメージ更新による作り直し | 同上 |

**復旧の拠り所は、2026-09-02 に手で作ったイメージ 1 つだけである。**
それも移送のために作ったものであり、以後の変更は一切入っていない。
スナップショットの定期取得は無い。

あわせて、ディスクが `boot_disk.initialize_params` で作られているため
**Terraform 上の独立した実体を持たない**（`auto_delete` は既定の `true`）。
インスタンスを作り直す変更（ゾーン移動・サブネット変更・ディスクの
`size` / `type` 変更）は、**plan には「変更」と出るが実体は置き換えであり、
Adobe の認証ごと持っていく。** いまは `deletion_protection` が最後で止めるが、
それは仕掛けであって構造ではない。

## 詳細

### 業務フロー

1. ブートディスクを `google_compute_disk` として独立させ、`prevent_destroy` を付ける
2. インスタンスは `boot_disk { source = ..., auto_delete = false }` で参照する
3. スナップショットのスケジュール（`google_compute_resource_policy`）を作り、ディスクに付ける
4. **スナップショットから復旧できることを一度実際に試す**

### 例外・エッジケース

- **移行はディスクを作り直さずに行えること。** `initialize_params` から
  独立ディスクへの移行が置き換えを伴うなら、それはこの要件の目的に反する
- Windows の VSS 整合スナップショットを使うかは、追加費用と復旧要件しだい

## スコープ外

- 生成そのものの機能変更（REQ-0020 の範囲）
- Adobe ライセンスの契約・台数管理

## 実装メモ

費用は 100GB のスナップショット数世代で月 ¥数百程度の見込み。
**`deletion_protection` があるので `-replace` は通らない。**
ディスクを独立させる作業自体に、その回避手順が要る。
