## 内容
製造委託先は、メーカーポータルから自社宛の発注資料をZIP形式でダウンロードできる。ダウンロードすると、対象の発注明細のステータスが自動で発注中から製造中に切り替わり、発注が確定する。

## 背景・理由
背景は未確認（既存実装からの逆算のため）。製造委託先が発注資料（発注リスト・製造データ・サムネイル）を受け取り、その受領を発注確定の合図として扱えるようにするため、ポータルからのダウンロードとステータス自動遷移を一体で行う必要がある。

## 詳細
製造委託先が発注資料をダウンロードすると、`TAPI_{メーカー名}_発注資料.zip` を生成して返す。ZIP にはタイプ別フォルダに発注リスト（Excel）・製造データ・サムネイルが含まれ、Tシャツは印刷位置別、アクスタはスタンドファイル（`_stand.ai`）を追加する。製造データが未完成（未ready）の明細は保留して資料から除外し、キャンセル明細も除外する。ポータルからのダウンロードはステータス更新の副作用を伴い、対象明細を発注中（ORDERED）から製造中（MANUFACTURING）へ自動遷移させる（管理者側のダウンロードは更新なし）。

主なエンドポイント:
- `GET /manufacturer-portal/order-documents` — 自社の発注資料ZIPをダウンロードし、対象明細を発注中→製造中へ自動遷移させる

## 受入基準

- [x] 製造データが未完成（未ready）の明細は保留され、資料に含まれない
- [x] キャンセルされた明細は資料から除外される
- [x] ポータルからダウンロードすると対象明細が発注中（ORDERED）から製造中（MANUFACTURING）へ自動遷移する

## 実装メモ
既存実装からの逆算で起票（status: done）。主なファイル:
- `GET /manufacturer-portal/order-documents`（update_status=True）— 発注資料ZIP（TAPI_*.zip）生成。タイプ別 Excel＋製造データ＋サムネ、未ready保留（_hold_unready_items）、キャンセル除外、アクスタ _stand.ai 追加。ポータルDL＝発注確定の副作用で ORDERED→MANUFACTURING。
- 管理者側の `GET /manufacturers/{id}/order-documents` は update_status=False でステータス更新なし（同一のZIP生成ロジックを共有）。
