## 内容

配送一覧の並び順を画面から変えられるようにしたい。

対象の列は **作成日／配送予定日／ステータス／注文番号／宛先** の 5 つで、
それぞれ昇順・降順を切り替えられる。**既定は作成日の降順**（現状の並びを維持する）。

## 背景・理由

現状は作成日の降順に固定で、画面から並び順を変える手段がない。
API（`GET /shipments`）は `sort_by`（`created_at` / `shipped_at` / `delivered_at`）に
対応しているが、配送一覧の画面からは配線されていない（REQ-0026 のスコープ外に記載済み）。
一覧に出ている「配送予定日」「注文番号」「宛先」「ステータス」は API 側にも並び替えの口がない。

## 判断が出ないと止まるもの

なし（2026-08-08 に対象列・既定の並び順・並び替えの適用範囲がすべて確定した）

## 詳細

### 並び替えの適用範囲

**並び替えは実配送（shipment）に対して効かせる。** 準備中注文（pending_order）は
従来どおり受注日の降順で並ぶ（ADR-0025 の決定：実配送の中だけ並べば足りる）。
配送一覧は実配送と準備中注文を別々に取得して連結しているため、
1 ページの中では「並び替えた実配送」→「受注日降順の準備中注文」の順に並ぶ。

### 入力・出力

`GET /shipments` の `sort_by` に次を追加する（既存の `shipped_at` / `delivered_at` は残す）。

| `sort_by` | 並び替えの基準 |
|---|---|
| `created_at`（既定） | 実配送の作成日時 |
| `estimated_shipping_date` | 配送予定日（`orders.estimated_shipping_date`） |
| `status` | 配送ステータス |
| `order_number` | 注文番号（`orders.order_number`） |
| `customer_name` | 宛先名（`orders.customer_name`） |

`sort_order` は `asc` / `desc`。指定がなければ `created_at` / `desc`。

画面側は一覧の各列見出しから並び替えを操作し、選択中の列と向きが分かるようにする。

### 例外・エッジケース

- **ステータスの並び順は業務上の進行順**（配送準備待ち → 配送準備完了 → 発送完了）にする。
  文字列の辞書順ではない
- **1 つの実配送が複数の注文を含む場合**は、注文番号・配送予定日とも**最小値**
  （最も小さい注文番号／最も早い配送予定日）を代表値として並べる。
  宛先名は現在一覧に表示している値（配送に紐づく最初の注文の宛名）を使う
- 配送予定日が未設定の実配送は、昇順・降順のいずれでも末尾に置く
- ページを送っても、選択した並び順が維持される

## 受入基準

- [ ] 配送一覧の「作成日」「配送予定日」「ステータス」「注文番号」「宛先」の各列から、
      昇順・降順を切り替えて並び替えられる
- [ ] 並び替えを指定していないとき、作成日の降順で表示される
- [ ] 選択中の並び替え列と向き（昇順／降順）が画面上で判別できる
- [ ] ステータスで並び替えたとき、業務上の進行順（配送準備待ち → 配送準備完了 → 発送完了）になる
- [ ] 並び替えが実配送（shipment）に効き、準備中注文（pending_order）は
      従来どおり受注日の降順で並ぶ
- [ ] ページを送っても選択した並び順が維持される
- [ ] 複数の注文を含む実配送が、注文番号・配送予定日とも最小値を代表として並ぶ

## スコープ外

- 実配送と準備中注文を通した一本の並び（ADR-0025 で「実配送の中だけ並べば足りる」と決定）
- 検索が機能していない不具合の修正 → BUG-0001
- 注文番号での検索と検索欄の表記 → REQ-0048
- 1 ページの表示件数が実配送と準備中注文で二重に効く件 → REQ-0050
