## 内容

GCP へ移行すると、API はリクエストを処理している間しか CPU が割り当てられない実行基盤
（Cloud Run）の上で動く。いま「レスポンスを返したあとに裏で走らせている処理」は、
そこでは最後まで走りきらない。

具体的には次の 2 つが完走しなくなる。

- **製造データの生成**（外部 VM を 30〜360 秒かけて呼ぶ）
- **受注通知メールの送信**

移行してから気づくと本番が壊れるので、**インフラを移す前に、実行基盤に依存しない形へ直しておく。**

## 背景・理由

現在の実装は `BackgroundTasks`（FastAPI がレスポンス返却後に実行する仕組み）に載っている。
`api/app/routers/orders.py` / `orders_v2.py` / `manufacturing_data.py` の 3 経路が該当する。

Railway では常時 CPU が割り当てられているため問題が表面化していないが、Cloud Run では
レスポンス後に CPU が絞られるため、製造データ生成が途中で止まる。止まった生成は
`generating` のまま宙吊りになり、発注ゲート（REQ-0021）が開かないまま滞留する。

あわせて、移行前に潰しておく必要がある実行基盤起因の不整合が 3 つある。

1. `web/next.config.ts` に `output: "standalone"` が無いのに `web/Dockerfile` の production
   ステージが `.next/standalone` を COPY している。**現状 production イメージがビルドできない**
   （フロントは Vercel で運用されており、誰も踏んでいない）
2. `NEXT_PUBLIC_API_URL` はビルド時に焼き込まれる（`web/src/` の 10 箇所で参照）。
   環境ごとに向き先を変える手段が無い
3. `alembic upgrade head` が API の起動コマンドに同居している。複数インスタンスが同時に
   起動するとマイグレーションが競合する

## 詳細

### 業務フロー

外部販売サイトからの受注（v2）を受けたとき:

1. API は `manufacturing_data` を `pending` で作成し、**即座に応答する**（生成はしない）
2. 別プロセスのワーカーが `pending` を掴んで、外部 VM を呼び、成果物を保存し、状態を更新する
3. ワーカーは処理対象が無くなったら終了する

受注通知メールは、レスポンスを返す前に**同期で**送信する。送信に失敗しても受注登録は成功させる
（ADR-0014 の方針を維持する）。

### 例外・エッジケース

- ワーカーが複数同時に起動しても、同じ製造データを二重に処理してはならない
- 前のプロセスが中断して `generating` のまま残ったものは、次のワーカー起動時に再駆動する
  （現在 `recover_stranded_generations` が API 起動時に担っている責務を、ワーカーへ移す）
- 外部 VM が未設定のときは、これまでどおり生成を無効として扱う

## 受入基準

- [ ] `web` の production イメージが `docker build --target production` で成功する
- [ ] `NEXT_PUBLIC_API_URL` をビルド引数で指定でき、指定した値が実行時のリクエスト先になる
- [ ] `api` の production イメージの起動コマンドに、マイグレーションの実行が含まれていない
- [ ] 外部注文 v2 の受信時、`manufacturing_data` が `pending` で作成され、レスポンス返却後に
      アプリ内で生成処理が走らない
- [ ] ワーカーのエントリポイントを単体で起動すると、`pending` の製造データが処理され、
      対象が無くなるとプロセスが正常終了する
- [ ] ワーカーを 2 つ同時に起動しても、同じ製造データが二重に処理されない
- [ ] 前プロセスで中断された `generating` の製造データが、ワーカーの起動時に再駆動される
- [ ] 受注通知メールがレスポンス返却前に送信され、送信に失敗しても受注登録は成功する
- [ ] DB 接続プールのサイズと最大オーバーフローを環境変数で変更できる
- [ ] `scripts/quality-gate.sh` の PROJECT_CHECKS（docs-lint / ruff / mypy / eslint / tsc）が
      すべて緑である
