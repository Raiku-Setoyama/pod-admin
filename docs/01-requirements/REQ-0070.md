## 内容

販売サイト rksyo に新商品「Tシャツ（左胸ワンポイント）」を出す。pod-admin ではTシャツの印刷位置
（position）に「左胸」を足し、製造データをアートボード右上の 100×100mm の枠に収めた PDF で出す。
発注書・ファイル名・PDF の書き出し方法は既存のTシャツと同じ。

## 背景・理由

rksyo 側は Raiku-Setoyama/rksyo#222 で実装済み。pod-admin が「左胸」を受け付けないと
受注が 400 になり、受け付けても全面印刷の製造データが出てしまうので、pod-admin 側の対応が要る。
設計の正本は rksyo の `docs/superpowers/specs/2026-10-19-left-chest-onepoint-tshirt-design.md`（§5.1）。

## 詳細

- `TshirtPosition` に `LEFT_CHEST = "左胸"` を追加する。外部 API の options と受注バリデーションは
  enum 由来なので自動で追従する。
- 生成の振り分けは `manufacturing_data.variant` に載せる（position 列は足さない）。
  tshirt で position が「左胸」なら `variant = "left_chest"`、「正面」または未指定なら `None`
  （既存行と互換）、それ以外は生成失敗（フェイルクローズ）。
- 生成は 297×406mm のテンプレートの右上に接する 100×100mm の枠に、既存どおり 1mm の余白・中央配置で
  画像を収める。テンプレート・レイヤー削除・PDF 書き出し・ファイル名は変えない。
- 開発用 seed に (tshirt, S/M/L/XL, 左胸, 白) の 4 行を足す。本番・ステージングの商品マスタは
  運用者が管理画面から追加する。

### 例外・エッジケース

- 既存の「正面」の製造データ行（variant NULL）はそのまま再利用される。
- 「左胸」以外の未知の position は受注時に 400、生成では失敗行になる。

## 受入基準

- [x] `GET /external/product-options?product_type=tshirt` の position に `正面` と `左胸` が出る
- [x] position「左胸」のTシャツ明細を受注でき、製造データ行の variant が `left_chest` になる。
  「正面」の明細は variant が NULL のまま（既存キャッシュと互換）
- [x] 「左胸」の製造データは、アートボード右上に接する 100×100mm の枠に収まった PDF になり、
  ファイル名・用紙サイズ・ICC は「正面」と同じ
- [x] tshirt で「正面」「左胸」以外の position は `MfgMappingError` / `GenerationError` で失敗する
- [x] 開発用 seed に「左胸」の 4 行が入り、API 文書に `左胸` が載っている

## スコープ外

- 受注時の商品照合を属性一致に変えること（現状は product_type の先頭 1 行）
- rksyo 側の変更（別リポジトリ）
- 本番・ステージングの商品マスタ投入（運用者が管理画面から行う）
