## 内容
外部の販売サイトは、APIキーによる認証を通じて、すでに完成しているデザイン画像（完成デザインのURL）を添えた受注を、本システムに登録できる。

## 背景・理由
背景は未確認（既存実装からの逆算のため）。外部の販売サイトで発生した注文を、担当者の手作業を介さずに受注管理システムへ自動で取り込むため、外部サイトから直接受注を登録できる入口（API）が必要となる。

## 判断が出ないと止まるもの
なし

## 詳細
外部販売サイトは、リクエストヘッダーにAPIキー（`X-API-Key`）を付与して受注登録APIを呼び出す。APIキーは登録済みの受注元と照合され、受注元が特定される。受注には7桁の注文番号を付与し、番号は重複を許さない（重複時は 409 を返す）。受注明細の内容を検証し、合計金額はシステム側で再計算する。受注日時（ordered_at）は日本時間（JST）で記録される。この方式（v1）では、明細に完成デザインの画像URLを添えて登録する。

主なエンドポイント:
- `POST /api/v1/orders` — APIキー認証で、完成デザイン付きの受注を登録する（注文番号7桁のユニーク性チェック、明細検証、合計金額の再計算、受注日時をJSTで記録）

## 受入基準
- [x] `X-API-Key` に登録済み受注元のAPIキーを付与して `POST /api/v1/orders` すると、受注が登録される
- [x] 注文番号は7桁で、既存の注文番号と重複する場合は 409（コンフリクト）を返す
- [x] 受注明細の内容が検証され、合計金額はリクエスト値ではなくシステム側で再計算される
- [x] 受注日時（ordered_at）が日本時間（JST）で記録される
- [x] 明細に完成デザインの画像URL（design_image_url）を添えて受注を登録できる
