## 内容

現状のコードベースで大量に失敗している静的解析（ruff / eslint / mypy / tsc）を是正し、品質ゲート（`scripts/quality-gate.sh` の `PROJECT_CHECKS`）と CI（`ci.yml`）の必須チェックとして有効化できる状態にしたい。緑化するまでは「導入予定」として非ブロッキングで可視化するに留める。

## 背景・理由

段階4（品質ゲート導入）の事前確認で、2026-08-06 時点の main で次の失敗が判明した。

- api（uv）: ruff 260 errors（174 自動修正可）／ mypy 1758 errors（116 files）
- web（npm）: eslint 5 errors・34 warnings ／ tsc 26 errors

このままフックや必須チェックで有効化すると push・マージが常に失敗し、体制そのものが放棄される。そのため docs-lint 以外のコードチェックはゲートから外している（`quality-gate.sh` の `PROJECT_CHECKS` はコメントアウト、`ci.yml` は continue-on-error）。是正して緑化すれば、これらを必須に昇格できる。

2026-08-06 に再実測したところ、**失敗の大半はテストコードに偏っている**ことが分かった（本番コードだけなら
ruff 70 件・mypy 143 件・eslint 5 件、tsc は 0 件）。総件数だけで是正範囲を判断すると実態を見誤る。
**内訳の実測値と、そこから導かれる選択肢は ADR-0021 が正本である。**

## 受入基準

ADR-0021 の決定（選択肢 B・全件一括）に基づく。件数は 2026-08-06 の実測値。

- [ ] `cd api && uv run ruff check .` がエラー 0 件で通る（`app/` / `tests/` / `scripts/` / `alembic/` のすべて）
- [ ] `cd api && uv run mypy .` がエラー 0 件で通る。`strict = true` を維持し、対象範囲を絞らない
- [ ] `cd web && npm run lint` がエラー 0 件で通る
- [ ] `cd web && npx tsc --noEmit` がエラー 0 件で通る
- [ ] ルールの除外は偽陽性に限る。FastAPI の `Depends()` / `Query()` に対する `B008` 除外以外に、
      指摘を消すためのルール無効化・`# type: ignore` の安易な追加を行っていない
- [ ] `scripts/quality-gate.sh` の `PROJECT_CHECKS` で ruff / mypy / eslint / tsc の 4 つが有効になっている
- [ ] `.github/workflows/ci.yml` の該当 4 ステップから `continue-on-error` が外れている
- [ ] `cd api && uv run pytest` と `cd web && npm run test:run` が是正前と同じく緑である（振る舞いを変えていない）

## スコープ外

テスト（pytest / vitest / Playwright）の CI 実行（DB・インフラ準備を含む）は本要件の対象外とし、別途扱う。

## 実装メモ

ADR-0021 で選択肢 B（全件一括）が採用されたため、**分割せず 1 本の実装 PR で出す。**
途中の状態（一部だけ緑）で必須化するとゲートが赤のままになり、中間状態がレビュー可能な形にならないため。

- ゲート: `scripts/quality-gate.sh` の `PROJECT_CHECKS` で 4 チェックを有効化する（現状は docs-lint のみ）。
- CI: `.github/workflows/ci.yml` の該当ステップから `continue-on-error` を外す。マージ後にブランチ保護の必須チェックへ昇格。
- 着手の足がかり: `uv run ruff check --fix`（174 件自動修正可）、eslint も `--fix` あり。mypy / tsc は手修正が中心。
