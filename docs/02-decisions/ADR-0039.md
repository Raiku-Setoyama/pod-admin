## 背景

製造データは、Windows VM 上の Adobe Illustrator（illustrator-vm）が ExtendScript で作っている。
費用（VM 月 ¥23,099 と Adobe のライセンス）がかかり、停止の原因がすべて Windows・GUI・
Adobe ライセンスにある（REQ-0067 の背景）。

OSS の VectorCraft（Rust 製、MIT / Apache-2.0）は Illustrator 相当の操作（画像トレース、
パスのオフセット、パスファインダー、CMYK 変換、.ai／PDF の書き出し）を、画面なしのコマンドとして
提供する。illustrator-vm の各商品の処理を移して検証したところ、中身は Illustrator 版と同等に作れた。
残る問題は 1 つで、**VectorCraft の .ai を Illustrator で開くとレイヤーが 1 枚にまとまる。**
製造委託先はレイヤー（カットライン・印刷・白版）を分けて作業する。

## 検討した選択肢

### 選択肢 A: 今の VM を使い続ける

- 利点: 何も変えない
- 欠点: 費用と停止の原因がそのまま残る

### 選択肢 B: VM と同じ API を持つ生成サービスを Cloud Run に置く

- 利点: pod-admin 側の変更が、呼び出し先 URL と認証だけで済む
- 欠点: サービス・サービスアカウント・IAM・ジョブ状態の置き場（GCS）・API の契約が 1 組増える

### 選択肢 C: ワーカーの中で直接生成する

- 利点: 増えるサービス・認証・状態管理が無い。HTTP の待ち合わせとポーリングも無くなる
- 利点: 生成のログがワーカーのログとして Cloud Logging に出る
- 欠点: 生成の依存（実行ファイル・ICC・テンプレート・画像処理ライブラリ）が pod-admin に入る

**弊社推奨**: C（コードを pod-admin に置くなら、増えるものが最も少ない）

## 決定

選択肢 C を採用する。あわせて次を決める。

1. **生成は `pod-admin-api` とは別のサーバーで動かす。** 生成の依存はワーカー用のイメージ
   （`api/Dockerfile` の `worker` ステージ）にだけ入れる。API のイメージには入れない。
   2026-10-11 にプロジェクト責任者が必須とした
2. **アクリル系（キーホルダー・スタンド・ステッカー）の .ai は、Illustrator 8 形式（PostScript ベースの旧形式）で書く。**
   Illustrator 2026 はこの形式をレイヤー付きで開ける。VectorCraft が書いた文書を、自前の変換で旧形式に書き直す
3. **T シャツ・トートは PDF のまま。** VectorCraft が書く目印用の空パスを取り除き、
   埋め込みの sRGB を標準の「sRGB IEC61966-2.1」に差し替える（製造委託先の指摘、2026-10-09）
4. **白版画像の抜けを自動で埋める。** 規則は REQ-0067
5. **VectorCraft はバージョンを固定する。** 実行ファイルはイメージのビルド時に取得してチェックサムで照合し、
   実行時には取りに行かない。更新は、自動テストと Illustrator 版との比較を通したものだけを採用する
6. **切り替え後もしばらく VM を残す。** 本番を切り替えたら VM は停止して残し、切り戻し先にする。
   撤去は REQ-0068 で行う

## 理由

- 費用は、VM と Adobe のライセンスで月 約 2.8 万円かかっていたものが、ワーカーの実行時間（1 件 1 秒前後）だけになる
- 停止の原因だった Windows の自動ログオン、GUI、Adobe のライセンス確認がなくなる
- 製造委託先がサンプル（キーホルダー・スタンド・T シャツ）で OK を出した。
  ステッカーはキーホルダーと、トートは T シャツと同じ形式なので、確認は不要とプロジェクト責任者が判断した
- Illustrator 8 形式は、20 年以上変わっていない固定の仕様である。
  変わりうるのは VectorCraft 側の文書の中身なので、そこを自動テストで守る

## 影響

- `api/app/generator/` に生成処理を置き、`api/app/services/illustrator_vm_client.py` を置き換える
- ワーカーの死活確認は、VM の `/health` ではなく生成処理の自己確認になる（ログの目印と監視も合わせて変える）
- 生成 1 件の最悪時間が短くなるので、ワーカー Job のタイムアウトの導出値（`generation_worst_case_seconds`）を変える
- 製造データ生成の ICC プロファイルとして、Japan Color 2001 Coated（Adobe 配布）と
  sRGB IEC61966-2.1（HP 配布、無改変での再配布は自由）をリポジトリに含める。どちらもイメージの外には配布しない

## 追記（2026-10-12）

決定 6（切り替え後もしばらく VM を残す）は、プロジェクト責任者の指示で切り替えの翌日に打ち切り、
VM を撤去した（REQ-0068）。切り戻し先は、VM の代わりにブートディスクのスナップショットとして残している
（`infra/README.md`「製造データ生成 VM の撤去」）。
