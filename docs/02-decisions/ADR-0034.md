## 背景

REQ-0053 は「ステージングの製造データ生成は、外部 VM を本番と共有すると本番のジョブ待ち行列に
混ざるため、当面は無効にしておく」と決め、`illustrator_vm_base_url` を空にした。REQ-0055 も
「ステージングから製造データ生成を利用できるようにすること」をスコープ外に置き、
**移送後に別途判断する**としている。

一方 REQ-0061 は、Railway を停止する前に **ステージングでも製造データ生成が動くことを確認したい**
という要求である。確認するには、一時的にせよステージングから本番と同じ VM へ繋ぐ必要がある。

「混ざる」という REQ-0053 の懸念は今も有効である。移行元の Railway では製造データ生成が現に
動いており、illustrator-vm は 1 件ずつの直列処理（最大約 300 秒、キュー 50 超で 503）だからである。

また、ステージングの停止は現在 **二重にかかっている。**

```
paused = var.worker_schedule_paused || var.illustrator_vm_base_url == ""
```

`illustrator_vm_base_url` を埋めると、この二重の守りが片方だけになる。

## 検討した選択肢

### 選択肢 A: ステージングの `illustrator_vm_base_url` を Terraform に入れる

- 利点:
  - 設定が IaC に残り、確認手順が再現可能になる
  - 追加の運用知識が要らない
- 欠点:
  - REQ-0053 が理由つきで決めた「当面は無効」を、移送前に恒久的に取り消すことになる
  - 二重の停止が `worker_schedule_paused` の 1 つだけになる。**この 1 つを誤って false にすると、
    ステージングが 5 分ごとに本番 VM の待ち行列へ入り続ける**
  - 確認が終わっても、繋がった状態が残り続ける

### 選択肢 B: 実行時オーバーライドで、確認のときだけ繋ぐ

`gcloud run jobs execute pod-admin-worker --update-env-vars ILLUSTRATOR_VM_BASE_URL=...` は
**その 1 回の実行にだけ**環境変数を上書きする。Job の定義は変わらない。

- 利点:
  - Terraform も Job の定義も変えない。`terraform plan` の差分が出ない
  - 二重の停止がそのまま残る。Scheduler は空 URL のガードで止まり続ける
  - VM に投入されるのは、確認のために自分で作ったテスト注文の分だけになる
  - 移送後に正式に繋ぐときは、A へ移るだけでよい
- 欠点:
  - 確認の手順が IaC に残らないので、手順書として別に残す必要がある
  - 実行のたびにフラグを付ける必要があり、付け忘れると生成が `failed` に落ちる

### 選択肢 C: ステージング専用の illustrator スタブを立てる

- 利点:
  - 本番 VM に一切触れない
- 欠点:
  - スタブは Illustrator を動かさないので、**確認したいこと（実際に成果物が生成されるか）が
    確認できない。** 要求を満たさない

**弊社推奨**: B（REQ-0053 の決定を取り消さずに、REQ-0061 の確認だけを通せる）

## 判断が出ないと止まるもの

## 決定

選択肢 B を採用する。移送（REQ-0055）が完了するまで、ステージングの
`illustrator_vm_base_url` は Terraform 上で空のままとし、疎通確認は
`gcloud run jobs execute` の実行時オーバーライドで 1 回ずつ行う。

## 理由

REQ-0053 の「本番のジョブ待ち行列に混ざる」という懸念は、**繋ぐこと自体ではなく、
繋ぎっぱなしで 5 分ごとに起動されること**にある。実行時オーバーライドは、繋がる範囲を
「人が明示的に起動した 1 回」に限定するので、確認に必要な分だけを取り出して懸念を残さない。

二重の停止を維持できることも大きい。設定が 1 つだけになると、誤操作が直ちに本番の
待ち行列へ波及する。**確認のために恒久的な安全装置を外すのは、費用対効果が合わない。**

## 影響

- コードベースへの影響: なし。`ILLUSTRATOR_VM_BASE_URL` は既に環境変数で切り替わる
- 運用への影響: ステージングでの生成確認は、毎回オーバーライド付きで Job を起動する。
  手順は REQ-0061 が残す手順書が正本になる
- この決定によって不可能になること: ステージングで製造データ生成を継続的に使うこと。
  ステージングの受注から自動で製造データが作られる状態にはならない

## 見直しの条件

REQ-0055 で illustrator-vm を会社組織のプロジェクトへ移送し、閉域の内部 IP で
到達できるようになったとき。そこでステージングからも常時繋いでよいと判断するなら、
選択肢 A（Terraform に URL を入れる）へ移る。
