## 現象

請求書PDFの発行が、**管理画面とメーカーポータルのどちらからも 500 エラーになる。**
PDF は 1 件も生成されない。

```
POST /api/v1/manufacturers/{id}/invoices        → 500 Internal Server Error
POST /api/v1/manufacturer-portal/invoices       → 500 Internal Server Error
```

サーバのログには次が出る。

```
File "/app/app/services/invoice_service.py", line 108, in _generate_invoice
  for order_item, order_number, _ordered_at, _customer_name, cost, _status in rows:
ValueError: too many values to unpack (expected 6)
```

## 再現手順

1. 管理者でログインする
2. 発注済みの受注明細を 1 件以上持つメーカーを選ぶ
3. その明細を指定して請求書PDFを発行する
   → 期待と異なり、PDF が返らず 500 エラーになる

メーカーポータル側も同じである（製造委託先でログインし、同じ明細を指定して発行する）。

| | |
|---|---|
| 発生環境 | ステージング（GCP、`https://pod-admin-api-kkwi54ngsq-an.a.run.app`）で確認。**環境に依存しない**（下記「原因」） |
| 発生頻度 | 毎回。明細の内容によらない |

## 違反している受入基準

> REQ-0030 の受入基準 1「`POST /manufacturers/{id}/invoices` で管理画面から請求書PDFを発行できる」
>
> REQ-0030 の受入基準 2「`POST /manufacturer-portal/invoices` でメーカーポータルから請求書PDFを発行できる」

**2 つとも満たされていない。**

## 影響範囲

**請求書の発行機能が全面的に使えない。** 管理者もメーカーも、誰も PDF を出せない。
回避策はない（他に PDF を出す経路が無いため）。

請求は月次の締め作業に直結するので、**本番稼働までに直っている必要がある。**

なお REQ-0030 の残り 3 つの受入基準（税率・請求書番号・宛先の書式）は、
PDF が生成される経路に入る前に落ちているため、**現状では検証できていない。**

## 原因

`InvoiceService._generate_invoice`（`api/app/services/invoice_service.py:108`）が
1 行あたり **6 個** の値を取り出そうとしているが、
`OrderRepository.find_ordered_items_by_manufacturer_detail`
（`api/app/repositories/order_repository.py:331`）が返すのは **8 個** である。

```python
select(
    OrderItem, Order.order_number, Order.ordered_at, Order.customer_name,
    Product.cost, OrderItem.status,
    Order.status,               # ← 後から足された
    Manufacturer.lead_time_days,  # ← 後から足された
)
```

リポジトリ側の docstring は 8 個と書いてあり、**呼び出し側だけが追随していない。**
発注一覧の機能追加でこの検索に列を足したとき、請求書側の展開が更新されなかった。

**取り出している場所は 1 か所だけである**（`grep "_ordered_at, _customer_name"` で確認）。
`generate_invoice_by_items` が唯一の入口で、管理画面とポータルの 2 つの経路が
どちらもここを通るため、1 つの原因で 2 つの受入基準が同時に落ちている。

**環境に依存しない。** タプルの要素数の不一致であり、Railway でも同じように失敗する。
GCP 移行（REQ-0053）が持ち込んだものではなく、ステージングの疎通確認で見つかっただけである。
