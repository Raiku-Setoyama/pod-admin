## 現象

製造委託先から至急の連絡があった（2026-10-26、江口さん経由）。

> ・アクリルフィギュア - 100x100mm - アクリル【個数】1個_1000174_1000115_1017
>
> カットラインが正常に作成されておりません。（添付の画像参照）

添付の画像（Illustrator の画面）では、絵柄はピアノを弾く女の子で、左に椅子、右にピアノがあり、
椅子とピアノの脚が床に着いている。本体の CutLine は**絵柄の下端付近の細長い形だけ**で、絵柄全体を囲んでいない。
形は、左端から小さな山を経て右端まで底辺に沿って伸びる線と、底辺中央の差し込みタブでできている。
生成はエラーにならず、製造データは製造委託先に納入された。

同じ製造データの印刷画像が透過されていない件は BUG-0004。

## 再現手順

**合成した入力での再現（確認済み、2026-10-26）:**

1. カットライン画像に、本体（楕円）と、底辺中央の土台（長方形）を描く。さらに土台の左右に、
   土台とすき間を空けて、**土台と同じ高さで下端が終わる脚**（細い長方形）を描く
2. `product_type=acrylic_stand` / `size=100x100mm` で生成する（ワーカー用／開発用のイメージで `app.generator.generate`）
3. → 期待と異なり、生成は成功し、本体の CutLine の高さが 26.5mm しかない（脚の無い入力では 76.5mm）。
   形は添付の画像と同じく、底辺に沿った線とタブだけになる

脚が土台より下へはみ出す入力（ADR-0038 の土台の延長が働く）や、脚が土台につながっている入力では再現しない。

**指摘の製造データ（1000174）の元データでの再現（確認済み、2026-10-26）:**

1. 販売サイトの本番 DB から、2026-10-17 のアクリルスタンド 100mm（販売サイトの商品 1405）の元データ
   （`submission_data` の design / cutline / shiroosae）を取得する
2. `product_type=acrylic_stand` / `size=100x100mm` で生成する
3. → 修正前のコードでは、本体の CutLine が幅 56.0mm × 高さ 11.0mm になる。Illustrator で開くと、
   製造委託先の添付画像と同じ形（左端の小さな山＋底辺の線＋タブ）である。
   カットライン画像は、左に椅子の脚、中央に土台、右にピアノの脚があり、椅子の脚が土台と同じ高さで床に着いている

## 違反している受入基準

> REQ-0067 の受入基準「アクリルスタンドの差し込みタブが ADR-0038 に従うこと（土台の延長、タブがテンプレートと同一、合成できなければ `failed`）」

タブは付いたが、本体の輪郭が失われたカットラインが成功として作られた。
ADR-0038 は、正しく合成できない入力を `failed` にして、壊れたデータを納入しないことを求めている。

## 影響範囲

- 指摘の 1000174 は、正しいデータが届くまで製造に着手できない
- 椅子・机・楽器など、脚が床に着く絵柄のアクリルスタンドで起こりうる。
  2026-10-12 以降に生成されたアクリルスタンドのうち、ほかに同じ状態のものがあるかは未確認
- 製造データは「受注元 × 商品コード × サイズ × バリアント」で再利用される（REQ-0020）ため、
  同じ商品の再注文にも同じデータが渡る
- 生成が成功扱いになるため、製造委託先が気づかなければ壊れたまま製造される。システム側で検知する手段が無い

## 原因

原因は 2 つが重なっている。どちらも `api/app/generator/geometry.py` の `merge_pedestal_tab` にある。

1. **最下点の高さにあるアンカーが、1 本の連続した辺（土台）に並んでいると決めつけていた。**
   タブを付ける位置は、最下点の高さにあるアンカーの左端と右端で決めていた。
   椅子やピアノの脚が土台と同じ高さで床に着き、土台との間にすき間があると、最下点の高さの辺が何か所にも分かれる。
   このとき「左端」と「右端」は脚と脚（または脚と土台）になり、その間をたどる向きの判定も外れる。
   結果として、**本体の輪郭ではなく、脚と土台の間のすき間の短い区間を本体として残し**、
   底の高さのアンカーはまとめて捨てていた。製造委託先の画像の「小さな山＋底辺に沿った線＋タブ」はこの形である
2. **合成の結果を確かめずに成功としていた。** 本体の外形が失われても、生成はそのまま成功した

脚が土台より下へはみ出す絵柄では、ADR-0038 の土台の延長で底辺が 1 本につながるので起きない。
脚が土台と同じ高さ（0.5pt 以内）で終わるときだけ起きる。

**修正:**

- 最下点の高さに続けて並ぶアンカーの列のうち、**タブの中心（本体の中心）の真下にある列を土台**とし、
  その列だけをノッチで置き換える。ほかの列（脚の底など）は本体の輪郭としてそのまま残す
- タブが土台に収まらないとき、または合成の結果、本体の外形（左右・上端）が変わったときは、
  生成を失敗させる（ADR-0038 の「合成できなければ `failed`」。壊れたデータを納入しない）

**同じ原因で他に壊れていないか:** タブの合成はアクリルスタンドだけが使う。
VM 版（illustrator-vm の `mergePedestalTab`）も同じ手順だったので、VM の頃から同じ絵柄では起きえた。
2026-10-12 以降のアクリルスタンドに同じ状態のものがあるかは、本番の製造データを見る権限が無く未確認（PR に記載）。
