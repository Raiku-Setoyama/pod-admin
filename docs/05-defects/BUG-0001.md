## 現象

配送一覧（`/shipments`）の検索ボックスに何かを入力すると、一覧に表示されている値を
そのまま（完全一致で）入力しても「該当する配送がありません」と表示され、結果が 0 件になる。

伝票番号でも、配送 ID でも、宛先の氏名でも同じ。**1 文字でも入力すると必ず 0 件になる。**

## 再現手順

1. 管理画面で配送一覧（`/shipments`）を開く
2. 一覧に表示されている行の「伝票番号」列の値をコピーする
3. 検索ボックス（プレースホルダ「配送ID、伝票番号、顧客名で検索...」）にそのまま貼り付ける
4. → 期待と異なり、一覧が空になり「該当する配送がありません」と表示される

配送 ID 列の値（先頭 8 桁）、宛先の氏名、任意の 1 文字でも同じ結果になる。

| | |
|---|---|
| 発生環境 | 本番（報告）。原因はコードにあり、PostgreSQL を使う全環境で発生する |
| 発生頻度 | 毎回。検索ボックスに 1 文字以上入力すれば必ず |

## 違反している受入基準

> REQ-0026 の受入基準 4「伝票番号・配送ID・顧客名で検索できる」

## 影響範囲

- **配送一覧の検索機能が全面的に使用できない。** 全管理者が影響を受ける
- 回避策は、ステータス・日付範囲のフィルターで絞ってから目視で探すことのみ。
  配送件数が増えるほど発送業務のコストが上がる
- データが壊れる種類の不具合ではない（参照のみ）

## 原因

原因は 2 つある。**1 つ目が「0 件になる」直接の原因**で、2 つ目はそれを直したあとに残る。

1. **UUID 列に対する `ILIKE` で API が 500 になっている。**
   `api/app/repositories/shipment_repository.py:100` が `Shipment.id.ilike(f"%{search}%")` を
   組み立てているが、`Shipment.id` は `UUID(as_uuid=False)`（PostgreSQL の `uuid` 型、
   `api/app/models/base.py:36`）である。PostgreSQL には `uuid` に対する `ILIKE` 演算子がなく、
   クエリが `operator does not exist: uuid ~~* unknown` で失敗する。
   `GET /shipments` が 500 を返し、フロント側は SWR のエラー時に空配列へフォールバックする
   （`web/src/features/shipments/hooks/use-shipments.ts:73`）ため、画面上は
   「該当する配送がありません」＝ 0 件として見える。
   検索語は `or_(...)` の中で常に評価されるので、**入力の内容によらず必ず失敗する。**

   PostgreSQL 16 で確認済み:

   ```
   postgres=# select * from t where id ilike '%abc%';
   ERROR:  operator does not exist: uuid ~~* unknown
   ```

2. **準備中注文（pending_order）が検索の対象外になっている。**
   配送一覧は実配送と準備中注文を統合して返すが
   （`api/app/services/shipment_service.py:141` `list_with_pending_orders`）、
   準備中注文を取る `OrderRepository.find_pending_orders()`
   （`api/app/repositories/order_repository.py:706`）は `search` を引数に取らない。
   1 を直しても、検索語に一致しない準備中注文が全件そのまま返り続ける。

同じ原因（UUID 列への `ILIKE`）で壊れている箇所が他にないかは、修正時に
`.ilike(` と UUID 主キーの組み合わせを全リポジトリで確認する。

## 受入基準

- [ ] 「再現手順」を実行しても再現しないこと
- [ ] 伝票番号・配送 ID（一覧に表示される先頭 8 桁を含む）・宛先の氏名のいずれで検索しても、
      該当する実配送（shipment）が結果に出ること
- [ ] 検索語を指定したとき、準備中注文（pending_order）も同じ検索語で絞り込まれること
- [ ] 検索語に一致するものが無いときだけ 0 件になること（API が 500 を返さないこと）
- [ ] 再発を検知する回帰テストが追加されていること

## スコープ外

- 注文番号での検索、および検索ボックスの表記の是正 → REQ-0048
- 一覧の並び替え → REQ-0049
- 実配送と準備中注文の統合方式（別々にページングして連結している現状）→ ADR-0025。
  この不具合は現状の統合方式のまま、準備中注文側にも検索条件を渡すことで直せる
