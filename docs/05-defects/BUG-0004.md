## 現象

製造委託先から至急の連絡があった（2026-10-26、江口さん経由）。

> 10/16、17、19分のRKSYO様の入稿データに不備が見つかりましたのでご連絡させていただきます。
>
> ・アクリルフィギュア - 100x100mm - アクリル【個数】1個_1000174_1000115_1017
>
> カットラインが正常に作成されておりません。（添付の画像参照）
> また、カラーデータの画像が透過されておりませんでした。
>
> ・アクリルキーホルダー - 50x50mm - アクリル【個数】1個_1000169_1000111_1016
> ・アクリルキーホルダー - 70x70mm - アクリル【個数】1個_1000170_1000112_1016
> ・アクリルキーホルダー - 70x70mm - アクリル【個数】1個_1000178_1000116_1019
>
> カラーデータの画像が透過されておりませんでした。

カットラインの件は別の不具合として BUG-0005 に起票した。
江口さんからは「以前と同じように、背景透過の画像になるように」との依頼。
VectorCraft 版の製造データのサンプル確認（2026-10-10）のときは、江口さんの側でもこの点を見落としていた。

アクリル系の製造データ（.ai）を Illustrator で開くと、ColorPrint レイヤーの画像が**透明な背景ごと白い四角**になっている。
Illustrator の VM で作っていた頃は、画像の背景は透過されていた。

## 再現手順

1. 背景が透明な印刷画像（販売サイトの color 画像はすべてそう）で、アクリルキーホルダー・アクリルスタンド・ステッカーの
   いずれかの製造データを生成する（ローカルではワーカー用／開発用のイメージで `app.generator.generate`）
2. 出力した .ai を Illustrator で開き、ColorPrint レイヤーを見る
3. → 期待と異なり、ColorPrint の中身が「画像 1 枚（RasterItem）」で、絵の外側が白い四角として残っている

| | |
|---|---|
| 発生環境 | 本番（2026-10-12 の VectorCraft 版への切り替え以降）。ローカルでも同じ入力で再現する |
| 発生頻度 | 毎回。背景が透明な印刷画像を使うアクリル系の製造データすべて |

## 違反している受入基準

印刷画像の透過を明文で定めた受入基準は無い。引用できる最も近い約束は次である。

> REQ-0067 の内容「製造委託先に渡すデータの中身は今と変えない。」

VM 版の製造データは、印刷画像の背景が透過されていた。製造委託先と依頼元が、以前と同じ透過を求めている。

## 影響範囲

- 製造委託先が、届いた製造データをそのまま使えない。指摘の 4 件は、データが直るまで製造に着手できない
- 2026-10-12 以降に生成されたアクリル系（キーホルダー・スタンド・ステッカー）の製造データは、すべて同じ状態のはずである。
  製造データは「受注元 × 商品コード × サイズ × バリアント」で再利用される（REQ-0020）ため、
  同じ商品の再注文にも同じデータが渡る
- 回避策: 製造委託先が Illustrator で手作業で切り抜く（運用上は求められない）
