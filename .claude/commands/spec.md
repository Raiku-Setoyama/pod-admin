対話型で仕様を作成し、確定後に **Taskツールを使用してサブエージェントを起動** し自動で実装を開始します。

要望: $ARGUMENTS

## 目的

**実装に必要な情報を漏れなく揃えた仕様**を作成する。
Phase 2（architect）以降がスムーズに進むよう、曖昧さを極力排除する。

---

## 動作フロー

### Step 1-4: 対話による仕様作成（Taskツール不使用）

この段階ではTaskツールを使わず、あなた自身が spec-writer として動作する。
`.claude/agents/spec-writer.md` を読み込み、その指示に従って以下を実行:

1. **要望の分析**: 以下の観点で不明点を特定
   - 対象ユーザー（誰が使うか）
   - 主要なユースケース（どのような場面で使うか）
   - 入力と出力（何を入力し、何が得られるか）
   - エッジケース（異常系・境界値の扱い）
   - 既存機能との関係（影響を受ける/与える機能）

2. **対話による明確化**: 不明点をまとめて質問する（1-3問程度）
   - 推測できることは「〜と想定しますが、よろしいですか？」と確認
   - 技術的な実装詳細は質問しない（architect に委ねる）

3. **仕様ドラフト提示**: 完全な仕様ドラフトを提示
   - スコープ（含めるもの/含めないもの）
   - 入出力の定義
   - 受け入れ基準（Given-When-Then形式）
   - 制約・非機能要件
   - 推測で補完した内容（assumptions）

4. **仕様確定**: ユーザーが「OK」「確定」「進めて」等と発言したら
   - `.claude/specs/FEAT-XXXX.yaml` に保存
   - 即座に Step 5 以降を自動実行

**早期承認の場合:**
ユーザーが「細かいことは任せる」等と言った場合は、推測で補完した上で仕様を確定する。

---

### Step 5-9: 自動実装（Taskツールを使用）

仕様確定後、以下を **Taskツールでサブエージェントを起動して** 途中で止めず最後まで一気に実行:

#### Step 5: 設計

**Taskツールで architect を起動する:**
```
Task(
  subagent_type: "general-purpose",
  prompt: """
  .claude/agents/architect.md を読み込み、その指示に従って動作してください。

  Intent Spec: <確定した仕様ファイルのパス>

  変更対象・アーキテクチャ判断・実装順序を決定してください。
  """
)
```

#### Step 6: テスト生成

**Taskツールで tdd-writer を起動する:**
```
Task(
  subagent_type: "general-purpose",
  prompt: """
  .claude/agents/tdd-writer.md を読み込み、その指示に従って動作してください。

  Intent Spec: <仕様ファイルのパス>
  設計メモ: <Step 5の出力>

  ユニットテスト + 統合テスト + E2Eテストを生成してください。
  テストが全て失敗する（Red）ことを確認してください。
  """
)
```

#### Step 7: 実装

**Taskツールで implementer を起動する:**
```
Task(
  subagent_type: "general-purpose",
  prompt: """
  .claude/agents/implementer.md を読み込み、その指示に従って動作してください。

  テストをパスするコードを書いてください。
  全てのテスト（ユニット・統合・E2E）がパスするまで実装を続けてください。
  """
)
```

#### Step 8: 品質ゲート

**Taskツールで quality-gate を起動する:**
```
Task(
  subagent_type: "general-purpose",
  prompt: """
  .claude/agents/quality-gate.md を読み込み、その指示に従って動作してください。

  6層検証を実行し、結果を報告してください。
  """
)
```

**FAIL の場合:**
- Step 7（implementer）に戻して修正（最大3回）
- それでもFAILなら人間に報告して終了

#### Step 9: PR作成

品質ゲート PASS の場合、Taskツールは使わず直接実行:
1. `git add` で変更をステージング
2. `git commit` でコミット
3. `git push` でプッシュ
4. `gh pr create` でPR作成

---

## 重要

- Step 1-4（対話フェーズ）は Taskツールを使わず、あなた自身が実行する
- Step 5-9（自動実装フェーズ）は **必ずTaskツールを使用してサブエージェントを起動する**
- サブエージェントには `.claude/agents/*.md` を読み込ませてその指示に従わせる
- 仕様確定後は途中で止めず最後まで一気に実行する

## 自動実行ルール

- **Step 1-4（対話フェーズ）**: ユーザーとの対話が必要
- **Step 5-9（自動実装フェーズ）**: 人間に承認を求めない
  - ファイルの読み書き、コマンド実行、Taskツール起動はすべて自動で進める
  - 質問や確認は一切せず、最善の判断で進める
  - 人間への報告が必要なのは以下の場合のみ:
    - 品質ゲートが3回連続でFAILした場合
    - 回復不能なエラーが発生した場合
