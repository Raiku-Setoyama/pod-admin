対話型で仕様を作成し、GitHub Issue として登録します。実装は行いません。

**参照スキル:** `.claude/skills/add-methodology/SKILL.md`（開発哲学・テスト戦略・Docker環境）

要望: $ARGUMENTS

## 目的

**実装に必要な情報を漏れなく揃えた仕様**を作成する。
`/ship` でのサブエージェントパイプラインがスムーズに進むよう、曖昧さを極力排除する。

---

## 動作フロー

### Step 1-3: 対話による仕様作成

`.claude/agents/spec-writer.md` を読み込み、その指示に従って以下を実行:

1. **要望の分析**: 以下の観点で不明点を特定
   - 対象ユーザー（誰が使うか）
   - 主要なユースケース（どのような場面で使うか）
   - 入力と出力（何を入力し、何が得られるか）
   - エッジケース（異常系・境界値の扱い）
   - 既存機能との関係（影響を受ける/与える機能）

2. **対話による明確化**: 不明点をまとめて質問する（1-3問程度）
   - 推測できることは「〜と想定しますが、よろしいですか？」と確認
   - 技術的な実装詳細は質問しない（planner に委ねる）

3. **仕様ドラフト提示**: 完全な仕様ドラフトを提示
   - スコープ（含めるもの/含めないもの）
   - 入出力の定義
   - 受け入れ基準（Given-When-Then形式）
   - 制約・非機能要件
   - 推測で補完した内容（assumptions）

**早期承認の場合:**
ユーザーが「細かいことは任せる」等と言った場合は、推測で補完した上で仕様を確定する。

### Step 4: GitHub Issue 作成

ユーザーが「OK」「確定」「進めて」等と発言したら、GitHub Issue を作成する。

1. **ラベル作成**（存在しない場合）:
   ```bash
   gh label create spec --description "Intent Spec" --color "0E8A16" 2>/dev/null || true
   ```

2. **Issue タイトル**: `<summary の内容>`

3. **Issue 本文**: `.claude/agents/spec-writer.md` の Issue フォーマットに従って作成

4. **Issue 作成**:
   ```bash
   gh issue create --title "<タイトル>" --body "<本文>" --label "spec"
   ```

5. **完了メッセージ**:
   ```
   ✅ GitHub Issue #<番号> を作成しました: <Issue URL>

   実装を開始するには以下を実行してください:
   /ship #<番号>
   ```

**Issue 作成失敗時:**
`gh` コマンドが失敗した場合（リポジトリ未連携、認証エラー等）はエラーを表示:
```
❌ GitHub Issue の作成に失敗しました: <エラー内容>
   gh auth login でGitHub認証を設定するか、リポジトリをGitHubに紐づけてください。
```

---

## 重要

- このコマンドは仕様作成のみを行い、実装は行わない
- 実装は `/ship #<issue番号>` で別途開始する
- Taskツールは使用しない（対話のみ）
- サブエージェントの指示は `.claude/agents/spec-writer.md` に従う
- **仕様は GitHub Issue として管理する**（ローカルファイルには保存しない）
- Issue 作成が必須。失敗した場合はエラーとして扱う
